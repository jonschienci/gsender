# Android Build 79 — kiosk edge controls

Build 79 starts from frozen Build 76, keeping Node 24.21.0 ARM64, USB serial 3.9.0, both web interfaces and backend functionality. Other chats' pending UI/USB/backend changes are excluded. Only native kiosk/activity handling and build labels changed.

Kiosk starts fullscreen. A top or bottom edge swipe reveals readable Android status/navigation bars, with temporary native padding. The first bottom swipe is guarded against immediately going Home; navigation controls become available after the reveal. Bars hide after three seconds and padding returns to zero. Automatic hiding waits for held touches to finish. Five taps on Build leave the managed session; another five re-enter it. Revealed Home/Recents can navigate away from the app; returning restores fullscreen. This is intentional access to Android's controls, not a claim that the app cannot be left. Notifications/shade and the power menu remain blocked.

Release assembly, lint, native/payload APK checks and five kiosk regression tests passed. The APK was reconstructed from verified Build 78 data for faster wireless transfer; its complete SHA-256 was checked on the tablet before installation. This produces the same standard signed APK as the ordinary build. Builds 77 and 78 were intermediate tests, superseded by Build 79.

Live L1008 Android 16 checks confirmed full 800×1280 content while hidden and a WebView rectangle of [0,28–800,1243] during top/bottom reveals. Both gestures stayed in gSender and auto-hid correctly. A seven-second held touch kept the bars/padding visible beyond the normal timeout; release restored fullscreen. The Status control was reachable while bars were visible. Paced five-tap exit/re-entry and persistence after a force-stop/relaunch were verified. A very fast synthetic ADB tap burst missed the exit; a paced sequence completed in 1.32 seconds succeeded. Keyboard/rotation and other tablet models are not validated by these checks. No CNC was attached; no motion or job simulations ran.
