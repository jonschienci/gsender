All 80 telemetry samples were valid. Android exit history was unchanged, and the captured logs contained no matching app crash, ANR, V8 heap failure or out-of-memory signature. No freeze was observed during the tested operations.

## What this does not establish

This is a functional validation of the benchmark kit and a small-file baseline. It does not reproduce or explain the previously reported crash. It does not establish a maximum file size, sustained USB serial performance, a memory-leak result, or precise touch-to-response latency. The capture includes setup, idle periods, parsing, rendering and streaming; its overall CPU/memory summary is not attributed to one isolated phase. Load markers include UI automation overhead and are not internal parser timings. A repeated unload/settle study has not yet been completed.

An earlier setup attempt used a 128-byte simulator buffer, below gSender grblHAL's initial sender window. That attempt is invalid for tablet performance assessment and is excluded from this table. The simulator was corrected to 1024 bytes before these runs.

## Next size ladder

Repeat each profile at 1, 5 and 20 MiB; complete three load/run/unload cycles and 30-second settled measurements at each size. Proceed to 50 and 100 MiB only while the preceding steps remain stable. Separate load/visualize tests from full streaming runs, and compare visualizer modes to locate memory growth. Stop at the first crash, sustained freeze, checksum failure or memory guard. A later isolated USB/controller test is needed to cover the USB driver.
