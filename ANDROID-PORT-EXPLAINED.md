## Runtime and platform boundary

Java `MainActivity` hosts the WebView; `EngineService` embeds Node on a dedicated thread in the application process. CMake builds `libgsender_bridge.so` against the selected `libnode.so`; `libc++_shared.so` is also packaged. This replaces Electron without adding a remote server or separate USB helper.

Build 57 uses upstream Node cross-compiled on Linux x86_64 with NDK 27.2.12479018 and 32-bit V8 host tools. `node-lts/` pins source hashes and the V8 ARM C++ parsing patch. OpenSSL assembly, Node's startup snapshot and Node code cache are disabled; V8's startup snapshot remains enabled. `-PnodeRuntimeRoot=… -PnodeRuntimeAbis=armeabi-v7a` selects this runtime and C++20 JNI compilation. Gradle discovers supplied runtime ABIs and rejects missing ones; the delivered APK still contains ARM32 only. ARM64 delivery is separate work. Without those properties, Gradle still selects the legacy Node.js Mobile 18.20.4 / C++17 build; that is not the distributed Build 57 runtime.

JNI exposes `process._linkedBinding('gsender_usb')`. Java callbacks enter V8 through a bounded `uv_async` queue, carrying JSON/Base64 payloads and monotonic queue age. Bootstrap multiplexes serial, Wi-Fi and BLE events to separate adapters. The native memory policy reserves system headroom from physical RAM, assigns two-thirds of the remainder to V8 old-space in 64 MiB increments, and caps 32-bit old-space at **1,536 MiB**; exact arithmetic is in `app/src/main/cpp/memory-budget.h`. The 2 GiB-device planning allowance is 1.5 GiB, not a reservation or total-process cap; native buffers, WebView and young-generation heap remain additional allocations. K90 receives the 1,536 MiB ceiling. Missing RAM information falls back to 2 GiB.

The tested Lenovo runs 32-bit Android 11 despite its CPU capabilities. Other tablets need ABI, WebView, USB-host and native-library/page-size validation. No custom ROM is required or bundled. Separate Lenovo tuning disables selected background apps/animations and adjusts power settings; those reversible device settings are not APK behavior or evidence of a portable custom Android image.

Fresh installations also require an up-to-date **Android System WebView**. The frontend compiles for Chromium 87, but that syntax target is not a guarantee that every newer WebView supports the complete UI. ZTE K87CA (Android 10) accepted Build 57 but displayed a blank page with WebView 83.0.4103.106; update WebView through Google Play and recheck launch. Samsung SM-X133 was updated through its official updater to Android 16 / One UI 8.5, build `BP4A.251205.006.X133DXU4BZH1`, security patch `2026-07-05`. Its Google Play system update reports `2026-08-01` and no further update available; the same Build 57 APK passed a cold launch afterward. Both advertise ARMv7 support and 4 KiB pages. Their launch checks are not USB/motion or performance validation. See [Build 57 installation status](android-port/BUILD-57.md).

## USB adapter and automatic SLB connection

`usb/js/esbuild-plugin.cjs` substitutes a Duplex adapter for `serialport`; `UsbSerialModule.java` uses Android USB Host and `usb-serial-for-android 3.9.0`. The adapter implements the consumed API subset. Requests have IDs and port-session IDs; unsolicited data/close events are session-scoped. Attachment paths are `android-usb:<device ID>:<port>` and are rediscovered after reattachment.

Writes resolve after driver completion; partial writes are never retried. Detach emits `close(error)` with `disconnected=true`. Initial DTR/RTS are asserted without a reset pulse. JNI input and JS receive buffers are bounded to 2 MiB and 1 MiB respectively. Permission handling covers cancellation, timeout, delayed callbacks and missed detach events.

SLB autoconnect requires exactly one eligible STM32 `0483:5740` or Pico SLB-Lite `2e8a:000a` first serial interface, existing Android permission, authenticated UI, and no active/pending controller connection. Android's USB intent reuses the Activity. Same-address failures retry with 2–30 s backoff; automatic attempts never open permission dialogs. Manual Disconnect suppresses that attachment until replug, while manual Connect remains available. The Android attachment filter includes both IDs. Discovery excludes ESP knobs, bootloaders and ambiguous multiple-board attachments; unrelated Pico products are not selected. Connection recovery does not resume jobs or issue motion/unlock/homing commands. GRBL/grblHAL initialization checks ownership after each asynchronous delay so teardown or controller replacement cannot trigger stale writes or false ready events.

Knob/tablet jog writes use `writeBounded` and `WriteDeadline.java`: **250 ms queue-plus-driver budget**, with expired work rejected before transmission. Ordinary CNC writes retain the upstream path. Firmware flashing is rejected before controller reset/close; unused flow-control operations remain unsupported.

## Bundle transforms, storage and lifecycle

`build-backend.cjs` substitutes Electron paths/logging, private home/i18n paths, flash handlers and local server integration. Checked source anchors fail the build when upstream changes; Vite's plain CSS/HTML substitutions also require inspection. Runtime packages remain external to esbuild and must be present in the pinned `runtime-deps/` manifest/lockfile. Explicit `acorn`/`acorn-walk` dependencies fix the earlier on-device startup failure.

The service replaces hashed payload files under private `files/runtime`, keeping settings under `files/data`. Both UI variants use `http://127.0.0.1:8765`. Each process generates a fresh credential; the Activity awaits `CookieManager.setCookie` before navigation. HTTP and Socket.IO authenticate it, bootstrap HTML is non-cacheable, and initial navigation has a unique query. Persisted remote-mode settings cannot change the loopback bind.

A foreground service and USB-active wake lock support backend operation. Recents removal closes transports and terminates the process, with a 1.5 s cleanup fallback; Node is initialized once per process. Home/background preserves the CNC service but cancels owned auxiliary jogging and revokes arming. Native visibility events reach the tablet pad even without a connected knob. Android document pickers replace desktop dialogs; the export bridge limits encoded transfers to 48 MiB.

## Frontend integration and performance

The stable desktop frontend and overlaid dev pendant compile separately. Compatibility changes supply the existing pendant preference/console actions and isolate required dev helpers. Startup reads `state.workspace.usePendantViewAsDefault`. Android fitting uses 1280 CSS pixels in landscape and 800 in pendant portrait with pinch disabled. Packaging injects Gradle's build number before React starts.

Pendant controls now use a compact 48 px header and 52 px bottom navigation, collapsible status, adaptive landscape/portrait DRO and jog containers, square jog buttons and segmented presets. CNC knob configuration moved from the header modal into a retained bottom-tray iframe; the standard interface keeps its launcher. Hidden panel display polling stops while connection presence/recovery remains active. Console and Macros have separate navigation panels; feed/spindle sliders share the updated layout. The expanded tray fits between the header and bottom navigation. Android’s status bar is hidden while the activity is open, with navigation retained and transient status access by edge swipe. Packaged layout overrides load after generated CSS to match the preview. Pendant pointer/touch cancellation clears long-press timers and stops held jogs; existing thresholds and native haptics remain.

**Build 54 UI:** The connection control includes machine state. File loading, recent files and the G-code list sit in the visualizer's file view; browser recent files retain up to five payloads in IndexedDB and fall back to the file picker when unavailable. The revised pendant includes paged Tools and Macros, a virtualized console, updated movement/macro forms, and the approved jog/DRO/axis-control sizing. Hidden console history uses a stable empty selector result to preserve Build 53's render suppression; opening it shows current history without clearing typed input.

**Builds 55–57 UI:** Jog increments and custom feed have compact numeric entry; custom feed follows Rapid and is stored in mm/min with mm/in display conversion. Ordinary jogging, held rim buttons and tilt use the selected feed; center dragging retains the Rapid cap. Work/Machine and units switches, larger header controls, individual axis actions, and the approved portrait/landscape layout are included. Numeric keypads preserve signed/decimal input and open after newly mounted fields receive focus. Machine-coordinate popups remain read-only and open until explicitly dismissed; Edit Work uses the current work coordinate. Holding Home places Home X/Y/Z/A controls over the matching axis-label slots, each targeting only that axis. Opening or closing the popup never triggers Home-all.

**Preview:** The pendant rasterizes dense geometry on a software worker canvas, maximum edge **1,600 px**, with native stroke batches limited to **512 segments**. Bounds/live-position overlays remain SVG. Build 51 replaced repeated PNG encode/decode with transferable `ImageBitmap` presentation in a canvas within the existing SVG viewport. Two bounded drawing surfaces are reused; covered pans reuse the current image, while zoom/resize/stroke changes or exposed geometry request a redraw. Superseded images/jobs are released or rejected; presentation failure invalidates the cache before PNG compatibility fallback. The GPU-worker experiment from Build 48 produced a measured Lenovo input-dispatch ANR and is not used; WebView presentation remains hardware accelerated. Both stable worker-buffer and newer segment-group formats are supported, without changing sent G-code precision.

**Builds 55–56 hybrid preview:** The worker indexes 512-segment blocks and evaluates visible density on pan/zoom. Sparse views use bounded SVG paths; dense views retain software raster rendering and bitmap presentation. The renderer preserves the previous layer until a current replacement arrives. Build 56 measures the full visible SVG world extent, including space outside a differently proportioned camera viewBox, for clipping, density and caching; resize/rotation refreshes it. This fixes locally reproduced blank toolpaths at settled zoom. No sent coordinates are simplified. Limits and regression evidence are in [HYBRID-PREVIEW.md](android-port/HYBRID-PREVIEW.md); Build 55 tablet measurements predate the clipping fix.

**Display delivery:** `runtime/serial-display.cjs` batches only socket copies of serial console output for clients negotiating `androidDisplayBatch: 1`. `android:serial-batch` flushes on a 100 ms timer, 128-entry/64 KiB thresholds, or an ordering barrier; legacy clients retain individual events. Parsing, ACK handling and CNC streaming are unchanged. Frontend listeners still receive individual lines, but history dispatches retain a bounded 300-line tail. Hidden consoles stop rendering/scrolling; the standard terminal also batches visible writes.

`ui/display-updates.mjs` replaces pending position-only/progress-counter snapshots until the next animation frame, with a 50 ms fallback. Machine state, pins, modal state, alarm, hold, completion and connection changes force ordered delivery. GrblHAL status polling/publication is 100 ms with the existing outstanding-request guard. Preview stages and explicit worker errors are recorded; a known preview failure stops a benchmark case, while readiness timeouts retain the last stage/UI state. These are display-path changes, not relaxed controller or jog freshness rules.

**Job storage:** `runtime/job-lines.cjs` indexes the original text rather than retaining one string per line, preserving filtering/order, hold/resume, start-from-line and rewind. Progress reuses parsed totals or cancellable chunked counting. Disabled logging avoids formatting work. Release shrinking retains JNI, WebView and reflected USB-driver entry points. Performance telemetry requires the explicit benchmark launch intent.

## Motion ownership: knob and tablet pad

The normal jog buttons/joystick use the pinned dev `JogStreamer`. Android knob and tablet XY controls retain their finite-command path through the same CNC USB owner. A new dev stream is rejected while auxiliary motion/cancellation receipts remain outstanding, preventing ACK ownership from crossing control paths.

**Knob:** Adaptive Precision → Rapid is now the default; Exact STEP remains selectable (0–10 mm, 0.1 mm grid). INPUT-v1 firmware, visible UI, valid mm presets/axis limits, fresh idle CNC state, empty queues and 300 ms fresh neutral evidence permit automatic readiness. Page/axis/STEP/mode/settings, control-owner or connection changes revoke current motion and require fresh release evidence. Legacy firmware is display-only in this flow.

`P2 INPUT` replaces the earlier ALIVE/PCAP/NCAP/VCAP/WHEEL/DETENT bursts with one boot/session/ticket/context-bound snapshot. It includes monotonic sample and turn counters, neutral state, selection/STEP/page, source period and age. Firmware constructs the latest snapshot after a busy BLE sender drains instead of queueing old frames. New contexts start with zero counters; mixed directions are discarded, repeated counters cannot renew motion, and expected enable-context acknowledgements prevent readiness oscillation. Rates are capped at 50 Hz active / 25 Hz idle; tickets expire at 100 ms, input at 250 ms. Physical XY still uses PAD and requires continuing source-contact reports.

Knob adaptive motion uses finite 60 ms segments with a 120 ms nominal queue budget and ACK/position evidence. An already-authorized long exact STEP may exceed that horizon during handoff; it is adopted without retransmission. Exact mode keeps an eight-turn expiring queue. These knob limits differ from the tablet pad below.

**Tablet XY:** The persistent Jog buttons / XY pad switch appears in both frontends. `ui/XYJogPad.tsx` retains Z/rotary controls but disables the pad in rotary mode. The circular pad has eight rim sectors: a short tap/release emits one saved Precise XY step. Holding past the configured jog threshold begins continuous movement at the selected feed, capped at Rapid; release stops without adding a step. Cancelled/slid/multitouch taps produce no step. A gesture begun in the enlarged center target stays captured when the finger leaves the pad and moves elsewhere on screen; heading is preserved while the dot remains within the circle. Its 6% dead zone and smoothstep radius map to Rapid feed with normalized diagonals and axis limits. One touch owns motion and disables the physical knob. Its fresh neutral disable acknowledgement is accepted without cancelling the tablet; actual knob changes or held/not-ready acknowledgements still stop it. Readiness is sampled before enqueueing its own status query.

Input updates run every 40 ms, at most one outstanding, with a **single-use 250 ms challenge and 250 ms motion-input lease**. An input stall cancels queued motion but can retain the finger session for up to **2 s**. A late packet is discarded and receives a new challenge; the UI immediately resamples the still-held finger. Only fresh input after drained cancellation receipts and fresh Idle can resume. Two seconds is contact retention, not permitted queued motion. Replay, invalid vectors, longer absence, release/capture loss, multitouch, background, settings changes, CNC faults or competing controls end contact; late replies cannot revive it.

The tablet queue is acceleration-aware: **180–500 ms nominal travel**, at most nine finite 60 ms segments and one unacknowledged write. Position evidence, not elapsed time alone, permits replenishment. Center/reversal cancels rather than draining the old direction. Motor-step/report rounding tolerance is capped at 0.05 mm; rounded endpoints retire only after all receipts and a subsequent fresh Idle. Stop reasons persist until the next valid center press. These software horizons are not physical stopping-time guarantees; slower acceleration can still limit achieved feed.

## Native tilt input

Tilt jog defaults off and never restores enabled at launch. `TiltSensor` samples gravity, or a filtered accelerometer fallback, on a dedicated Android handler thread. Native sample freshness is **150 ms**; display rotation is locked to the current perspective while enabled and restored on exit. Face-up flat neutral is required for 0.4 s. The current curve has a **6° dead zone**, full selected Precise/Normal/Rapid feed at **40°**, and a **60° cutoff**. Diagonals share the vector feed limit. The automatically displayed pad shows requested direction/intensity, not measured CNC position; it is passive while tilt owns control.

Tilt feeds the bounded tablet planner with exclusive knob ownership. Live preset changes cancel the prior queue before using the new ceiling. Z taps/holds share finite XYZ planning: per-axis feed/acceleration and total vector limits apply; finite taps execute once per fresh step ID. Explicit Z can operate during XY calibration or invalid tilt samples but cannot authorize XY. Z release/reversal cancels the shared jog queue, then fresh XY can resume after cancellation confirmation without recalibration. Ordinary Z handlers apply when tilt is off.

Touching other controls pauses tilt; machine controls, background or focus loss disable it. Sensor/link interruptions enforce neutral/freshness checks, and UI leases still gate Z. The USB validator permits only ordered bounded finite XYZ commands and retains the 250 ms write deadline. A compact readiness light reports ready/calibrating/unavailable without additional status polling. Full sensor-to-machine response and stopping behavior require physical validation.

## Bluetooth transport and recovery

USB remains the default knob transport; Bluetooth is the normal wireless alternative and the CNC remains on USB. Legacy Wi-Fi code remains for rollback. Scanning **PAIR BLUETOOTH** stores QR identity/key in process memory and connects automatically; restart requires rescanning. INPUT-v1 readiness is automatic; manual Arm/Disarm controls are absent.

**Bluetooth connects without discovery.** GSB1 carries the ESP32-C6 Wi-Fi STA/base identity; the shipped four-universal-MAC firmware derives its public Bluetooth address by adding 2 to the final octet modulo 256, without carry. Android calls `getRemoteDevice(...).connectGatt(...)` directly and still validates service/characteristics/MTU and QR-key authentication. This firmware-specific mapping needs a versioned QR containing the actual address if future firmware uses custom/random addressing.

The APK declares no location permission/feature, Bluetooth SCAN or legacy Bluetooth ADMIN. Android 8–11 use install-time Bluetooth permission; Android 12+ request CONNECT/Nearby devices. Camera permission remains necessary for QR scanning. Location Services can stay off; no OS Bluetooth bond is used.

Java handles GATT/ciphertext; Node/OpenSSL implements mutual HMAC-SHA256 proof, HKDF-SHA256 and directional AES-256-GCM with strict sequence/replay checks. MTU must be at least 247; packets hold one bounded P2 line with one response-write outstanding. Native queues expire after 50 ms, response writes after 100 ms; JNI queue age prevents stalled input appearing fresh. The address selects a peer, but the QR key authenticates it. No new crypto/Bluetooth library is added.

Wireless loss cancels/discards owned motion and reconnects with bounded backoff while visible. Authentication silence may retry; invalid proof/ciphertext replay stops retries. A healthy firmware reboot establishes new crypto/P2 sessions. Readiness requires new neutral/CNC evidence and resolved old receipts; no pre-loss motion replays. Disconnect stops retries. See `pendant/INPUT.md`, `BLE.md` and `TABLET-XY-PAD.md` for current contracts; older manual-arming sections are historical.

## Packaging and validation

Build backend and **both** Vite frontends before packaging. Vite runs with `--configLoader native` to avoid the bundled config loader’s CommonJS `node:path` failure. Payload assembly replaces dependencies, excludes native desktop `.node` modules/test fixtures, and generates the embedded ZIP/hash. Use JDK 17 and serial test execution (`--test-concurrency=1`; fixtures share port 8765). For Build 57, supply the explicit Node 24 runtime properties to release assembly/lint and verify the APK with `--abi armeabi-v7a --runtime-version 24.21.0`; the default build script alone selects the legacy runtime. Preserve the signing key and retain release mapping/provenance artifacts. Increment Gradle and backend version metadata together.

Build 57 logs record **335 passing regression tests**, both frontend builds, release assembly/lint, signature and APK/runtime verification. Coverage includes display delivery, hybrid clipping/resize, decimal entry, persistent Work/Machine popups, named-axis homing, USB recovery and jog regressions. The packaged UI passed portrait/landscape checks. Both new tablets received an APK whose installed SHA-256 matches the release; Samsung cold launch succeeded after its system updates, while ZTE launch remains deferred pending its WebView update. [Build 57 release notes](android-port/BUILD-57.md) record current device status. ## On-tablet benchmark and measured limits

**Tools → Benchmark** opens an offline quick check or seven-case full suite in both interfaces. A Node worker hosts a simulator on a random loopback TCP port. A shared connection gate blocks physical USB/network opens and autoconnect while the benchmark owns that endpoint; ordinary motion/knob/tilt polling and program event macros are suppressed. It exercises the actual loader, sender, display updates and renderer without requiring a Mac, external network or physical CNC.

The suite targets 500 acknowledgements/s with a 1,024-byte RX buffer. Contour, arcs and the 4.77 MiB mountain-relief fixture complete with canonical count/SHA-256 verification: **328,139 commands total**. Generated 5/20/30/40 MiB jobs fully load/preview, then stream for timed samples of at least 65 s; they are never reported as complete deliveries. Exercises include panning and 2× viewport zoom, classified against simulator timestamps so delayed UI polling cannot relabel post-stream frames. Compressed fixtures carry provenance/hashes and are unpacked before load timing.

Reports persist under private `files/data/benchmarks/<session-id>/`: atomic summary JSON plus append-only events, 12-session retention and an 8 MiB event cap. Interrupted sessions recover as interrupted on restart; export uses Android's file picker. Stop, backgrounding, available memory below 256 MiB or a 60 s UI-heartbeat lapse terminate a run. Host-app PSS includes Node but excludes the isolated WebView renderer; do not add Node RSS to it or compare it directly with the earlier combined-process PSS metric. The simulator itself uses tablet CPU/RAM.

All three Build 53 full-suite runs completed with matching checksums for the three complete jobs and zero RX overflows.
